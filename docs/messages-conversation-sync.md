# Messages 缓存与增量同步

## 进入页面

Supabase 恢复账号后，按 Hub 环境和账号 ID 同步读取本地会话摘要、分组与 Bot 筛选。鉴权初始化期间，加载壳展示不可交互的缓存列表；鉴权完成后切换到正常列表。首次没有缓存时展示骨架，首批最多 100 个变化房间返回后立即展示，再继续获取后续批次。旧 Human 成员接口只在身份初始化完成后后台加载，供其它界面兼容使用，不阻塞首屏。

缓存与消息历史分开，包含会话名称、最后消息摘要、未读、成员预览和权限摘要。它不保存 token，也不授予接口权限。退出登录清除当前账号的目录缓存；切换账号隔离数据和进行中请求。存储损坏、禁用或超额时退回内存；网络失败保留列表并提供重试。

## 同步协议

`POST /api/conversations/sync` 接收 `{ known: { room_id: revision }, limit: 100 }`，返回 `account_id`、`human_id`、`upserts`、`removed_ids` 和 `has_more`。

服务端每次按 Human 和全部自有 Bot 的当前成员关系重新检查权限，一次批量构造个人会话摘要，不包含 Team 房间。摘要指纹覆盖消息、名称、成员、权限、撤回和已读状态。客户端合并变化，移除失去访问权的房间，保留未变化房间。下一批使用已更新的版本清单，不使用容易因插入消息发生偏移的 offset。多个 Bot 共处一个房间时保留全部 Bot 来源，任意对应 Bot 筛选都能找到它。

这属于**版本清单差分传输**，并非持久化事件日志/cursor：服务端每次仍批量计算所有可见房间的摘要，客户端仍上传版本清单。最新消息和未读在 SQL 中去重、排名和计数，避免逐 Bot 查询及将所有历史消息读进 Python。大账号/长历史下的数据库代价仍需生产观测，后续可以维护持久化会话投影及变更序列。当前每次请求最多接受 20,000 条已知房间版本，单批最多 200 条变化；客户端每轮最多取 100 批，后续轮询可以继续。

## 排序与实时更新

目录只按最后有效 `message/system` 的时间倒序，同时间以房间 ID 稳定排序，无消息房间置后。渲染层继续支持置顶优先和设备上的隐藏水位。Messages 使用目录摘要作为时间、作者、预览的统一来源，不再被消息历史缓存覆盖。typing、ack、result、error、状态回执不会更新活动时间。撤回更新预览但不抬高时间。

进入 Messages、回到前台、Realtime 重连都会同步。订阅 Human 和全部自有 Bot 的通知；消息提示可以先更新已有摘要，再请求权威变化。每 30 秒补偿同步目录；打开的房间保留原有 5 秒消息补偿。并发合并、账号请求版本和房间本地版本防止旧响应覆盖新账号或刚到达的消息。

## 验证

- 后端全量：`cd backend && uv run pytest tests/ -q`，1771 passed、31 skipped。
- 会话接口：鉴权、排序、投递去重、回执、未读、撤回、重命名、成员/所有权撤销、多个 Bot、分页中新增变化。
- 前端全量：`cd frontend && pnpm vitest run`，805 passed；耗时基准默认跳过。
- `cd frontend && pnpm run build` 通过。
- 显式基准：`cd frontend && BOTCORD_CACHE_BENCHMARK=1 pnpm vitest run src/components/dashboard/conversation-cache.benchmark.test.tsx`。

基准用实际 React 组件和 store，100 个模拟房间，真实 localhost HTTP，固定响应延迟 1500ms。本次无缓存 DOM 出现 1580ms；重入后缓存加载壳 DOM 出现 43ms，最新变化在 1612ms 合并。两次响应分别返回 100 和 1 个房间。结果保存在 `frontend/docs/conversation-cache-results.json`。这是 jsdom 的 DOM 时序，不包含 Supabase session 恢复、浏览器绘制或生产后端耗时。当前没有可连接的浏览器，未完成明暗主题/移动端截图验收。
