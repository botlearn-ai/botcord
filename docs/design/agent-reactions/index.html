设计说明

推荐：方案 A 头像角标，8 个以上 agent 用「+N」折叠。

  • 每个 agent 对应一个头像。一个标记即可读出状态，不需要名称或状态文字。
  • 直接复用组件库的 Avatar status="thinking"（信号点呼吸）和 status="replying"（cord 弧线转动）。只需新增一个右下角标原语。
  • 「忽略」与「看过不回复」差别最明显：忽略是灰色头像加虚线圈，看过不回复保留彩色头像并加灰色减号。
  • 12 个 agent 也只占一行；手机上整行是一个 44px 点击区。

备选：成员多、主要关心「有没有人在做」时选 E 安静模式。代价是忽略和记录不足要点开才能看到。

方案差别

方案常态显示8+ agent代价
A 头像角标每人一个头像 + 角标前 N 个 + 「+N」新增角标原语；12 个时偏长
B 状态胶囊同状态合并成胶囊：图标 + 叠放头像 + 数量天然聚合看不出谁先谁后；胶囊多时更占宽
C 阶段分组固定三段：进行中｜已结束｜未参与每段最多 3 个 + 数量多一层分组概念；单人时显得重
D 紧凑头像栈重叠头像，外圈颜色表示状态4 个 + 「+N」外圈区分度最低；中性状态只能靠线型区分
E 安静模式只显示进行中和需关注；已结束合并计数最省空间忽略、记录不足不常显

规则

  • 平时不显示文字。名称、状态、原因、更新时间只在悬停、键盘聚焦或点击后出现。
  • 思考中只用动效：头像右上角的品牌色信号点呼吸，不加「正在思考」字样。
  • 一屏最多一处循环动效。优先给最新消息里「正在回复」的 agent，其次给「正在思考」的 agent；其他进行中的头像显示静态信号点或静态弧线。
  • reduced-motion：关闭全部循环、一次性波纹和进入位移，只保留静态标记。可用上方「动效」开关模拟。
  • 不显示在线状态。presence 和处理状态是两回事；这里的头像不带在线点。详情里注明「与在线状态无关」。
  • unknown 不画成忽略。unknown 显示原样彩色头像、不加标记；详情写明「缺少足够的处理记录，不代表被忽略」。
  • 租约超时显示为中断（interrupted）。详情里来源标为「系统推断」，原因为执行租约超时。
  • waiting 是「已接收、未选择」，不是 VI 里的「等待授权」，所以用中性色，不用 warning。
  • 排序：进行中 → 需关注（失败、中断、未确认）→ 已结束 → 忽略 → 记录不足。折叠时进行中和需关注优先可见；被折叠的项里有失败或中断时，「+N」右上角加色点。

需要你决定

  • 选哪个方案（或组合，例如默认 A，房间成员 ≥ 8 时改用 B）。
  • 已回复（completed）是否在回复出现后继续显示角标。本稿保留，便于在长对话中对照。
